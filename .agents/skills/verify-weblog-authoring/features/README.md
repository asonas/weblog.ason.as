# 管理画面の検証地図

管理画面（`/authoring/*`、`/draft-editor`）のユーザーから見た振る舞いを検証するための、維持される入口。操作の前にこの索引を読み、該当する機能ファイルを手順として使う。

## 基準状態

- `scripts/launch.mjs` で `http://127.0.0.1:15182` に起動した、空の一時DBのインスタンス。かけら形式を扱う機能は `--pieces` を付ける。
- `scripts/doctor.mjs` の全項目が `OK`。
- このインスタンスでは常に編集権限がある（`can_edit=true`）。ログインの操作は不要。
- 自分が起動していないインスタンスは操作しない。

## 操作の約束

- 各手順は基準状態から始める。DBは起動ごとに空になるので、手順の中で必要な記事を画面から作る。
- 要素はroleとaccessible nameで指定する。執筆メニューは `navigation`「執筆メニュー」で、リンクの名前は表示文字列ではなくaria名（「新しい記事を書く」「今日の日記を書く」「記事一覧」「Webmentionを管理」「端末を管理」）。
- 手順は `scripts/drive.mjs` に渡すジャーニーとして書く。

## 証拠と報告

- 操作と結果の状態を両方残す。保存を伴う機能は、APIからの読み直しか別のブラウザコンテキストでの再表示を添える。
- 証拠には機能IDと使った入口を書く。
- 到達できない経路は、試した操作と満たせなかった前提を報告する。別の入口で代えて検証済みとしない。

## 機能ファイルの形

各ファイルはH1とユーザーから見た振る舞いの1段落で始まり、次の4つのH2をこの順に持つ: `Sub-features`、`How to get to it (user POV)`、`Driving it with drive.mjs`、`Gotchas`。

## 機能

- [記事の執筆と保存](./draft-editor.md): 新しい記事の作成、端末とサーバーへの保存、再読み込みと別端末での復元。証明済みジャーニーあり。
- [記事一覧と管理](./article-administration.md): 一覧表示、状態フィルター、行メニューからの削除、今日の日記。
- [端末のペアリング](./mobile-devices.md): QRコードの発行、ペアリングの完了、期限切れ。
- [Webmentionの管理](./webmentions.md): 状態タブの切り替え。
