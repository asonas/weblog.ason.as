# 公開記事のWikiリンク先読み取り

Issue [#185](https://github.com/asonas/weblog.ason.as/issues/185) の実装と、2026-09-27 JST のローカル計測。

記事本文のWikiリンク名だけを抽出し、公開ルート表の主キーから公開headと有効な版を取得する。下書きや未公開の版は参照しない。リンクのない記事ではリンク先の問い合わせを発行しない。未作成リンクの関連ページ一覧は従来どおり別の処理であり、この変更の対象ではない。HTMLの配信経路、CloudFront、本番データ、既存HTMLの再生成方法は変更していない。

## 同一fixtureでの比較

`mise exec -- ruby -Ilib scripts/measure-public-wiki-reads.rb` で再計測できる。SQLiteに公開済みの人工記事を1,000件作り、本文に既存リンク `[[KORG multi/poly]]` と未作成リンク `[[未作成]]` を含める。変更前と同じ全件取得、および限定取得で同じ記事を描画してHTML全文を比較した。読み取り時間は各5回の中央値。記事表示全体の時間ではない。

| Wikiリンク先の読み取り | 取得した公開記事 | 取得した本文のバイト数 | ローカル中央値 |
| --- | ---: | ---: | ---: |
| 全件取得 | 1,000 | 1,216,822 | 14.795ms |
| 公開ルートから限定取得 | 1 | 1,218 | 0.170ms |

HTML全文は一致し、SHA-256 は `de77564c857941c7c3f37e561a56ecdece6f2a5d2531c0099527a2efc94783cf`。SQLiteの `EXPLAIN QUERY PLAN` は、ルート、head、版の順に既存の主キー索引を使用した。これはSQLiteの実行計画であり、DSQLの計画や費用の証拠ではない。計測値はローカル環境と人工データに限定される。

## DSQLと費用の境界

今回の実装コードを使ったAWS/DSQL計測は未実施。追加のAWS呼び出しは0回、追加費用は0ドル。以前の隔離実験 [#182](https://github.com/asonas/weblog.ason.as/issues/182) では、同形の3表の主キーを使う問い合わせの `EXPLAIN` 推定Read DPUは0.00326、全件方式は3.06742だった。実験全体は59回のAWS呼び出しで、観測したDSQLとLambda実行時間の小計は約0.0021ドルだった。この数値は今回の実装の測定値でも、本番の請求予測でもない。返却行数が少ないことだけではDPUが少ないと判断できない。

今回の変更をDSQLで確認する場合は、隔離した人工データに限り、各方式の `EXPLAIN` と表示を合計12回以内、追加費用1ドル以内を上限として開始し、使用量を確認して削除する。実行前に当時の料金を再確認する。現時点でそのAWS確認は残っている。
