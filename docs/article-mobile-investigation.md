## 再現

CSS・JSは通常どおり読み込む。比較のために加えた寸法指定とヘッダー初期化による移動を除き、画像の解放直前から計測する。

```sh

mise exec -- node /tmp/weblog-article-shift.mjs --reserve
```

本番の先頭本文画像にはwidth/height属性がなく、読み込み前の領域が確保されない。
width/height属性だけを付ける検証では改善しなかった。既存CSSの `width: auto` を検証用画像に限り実寸の4096pxへ置き換えると、`max-width: 100%` の制限で最終表示を維持したまま領域が確保された。
この試験では画像やコンテンツを削除せず、元画像のまま検証している。
CLSゼロはこの画像読み込み区間の値であり、ページ全体のLighthouseスコアや全コンテンツのCLSを保証しない。

## 修正方針

1. 公開HTMLの生成時にローカル画像の実寸を渡し、画像読み込み前から正しい縦横比を確保する。小さい画像の引き伸ばしを避け、読み込み後の配置・寸法は維持する。
2. ヒーローと本文画像へ画面幅・画素密度に応じた候補を用意する。高解像度の元画像を残し、先に生成した縮小版をsrcset/sizesで選択する。閲覧時のサーバー変換は追加しない。
3. 同じ記事・画像・画面幅を使って変更前後の最終画面を比較する。画像遅延時の段落移動、横はみ出し、ユニバースの操作も確認する。
4. 将来の反映時にはコードのデプロイだけで完了とせず、対象記事のHTML再生成とキャッシュ更新が必要。まずこの1記事で確認してから対象を広げる。

## 寸法保存とスケルトンの実装

新規画像の寸法はクライアントで取得する。
ブラウザは変換後のアップロード対象ファイルから既存の画像ヘッダー解析で幅・高さを取得する。
iOSは回転補正・縮小後の画像の幅・高さを送り、アップロード再送用の記録にも保存する。
署名URL発行時に画像URLをキーとして `image_dimensions` に保存し、インボックスから公開画像へコピーするときは寸法も引き継ぐ。
寸法の登録は、画像ファイルのアップロード成功を意味するものではない。

公開処理はDBの幅・高さからHTMLを生成し、寸法取得のためにS3の画像を読まない。
寸法未送信の旧クライアントもアップロードは継続できる。未登録画像は従来の表示を維持し、公開時のサーバー解析は行わない。

画像読み込み中の表示はCSSの疑似要素・グラデーション・アニメーションで表現する。
既存の読み込み完了・失敗判定に合わせて消し、動きを減らす設定では静止させる。
読み込み完了後の画像の寸法・配置・ファイルは維持する。
画像取得失敗時に変わるインライン画像のベースライン余白も保持する。

## 既存画像の移行

DBスキーマ更新後、認証済みの環境から対象を確認する。

```sh
mise exec -- ruby bin/backfill-image-dimensions --host DSQL_HOST --site-bucket SITE_BUCKET
mise exec -- ruby bin/backfill-image-dimensions --host DSQL_HOST --site-bucket SITE_BUCKET --apply
```

`--apply` がなければ画像一覧と件数の表示のみ。
バッチだけが未登録画像をS3から取得し、回転補正を考慮した幅・高さを保存する。
登録済みの画像は再解析しない。取得・解析できない画像は一覧に残し、終了コード1で報告する。
対象はassets配下のJPEG・PNG・WebP・GIF。生成済み縮小版・インボックスのサムネイルは除く。
寸法登録後、公開記事のHTMLを再生成してキャッシュを更新する必要がある。反映はまず1記事で検証する。
