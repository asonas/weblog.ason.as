# トップページの読み込み表示と調整手順

## 表示方針

読み込み中と取得後で、ヒーローのタイトル・抜粋の枠、タグ領域、記事一覧の開始位置を揃える。ヘッダーの検索やサイト案内はデータ取得を待たずに表示する。

ヒーローはタイトルと抜粋をそれぞれ最大2行に省略する。スケルトンは2行を想定するが、実際のタイトルは文字数に応じた高さになる。全文は記事へのリンク先で読める。抜粋がない記事では抜粋要素自体を表示しない。外枠の高さを共通化し、タイトルの長さによらず後続セクションの位置を保つ。

タグは取得前に数と幅を予測できないため、仮のピルを並べず「タグを読み込み中…」を表示する。PCでは3行分を確保し、4行目以降がある場合だけ「すべて表示」と開閉ボタンの領域を描画する。ボタンのない空の領域は確保しないため、取得後にボタンが必要になった場合は記事一覧が44px下へ移動する。スマホでは2行の横スクロールとし、開閉ボタンは表示しない。

## 調整箇所

| 対象 | 実装 | 現在の設定・注意点 |
| --- | --- | --- |
| ヒーローの外枠 | `frontend/authoring/cardHome.css` の `--home-hero-height` と `.cover-journal__hero` | PC 38rem、600px以下は420px。読み込み中も同じクラスを使う |
| タイトル | 同ファイルの `.cover-journal__lead > strong` | PC `clamp(40px, 6.25vw, 90px)`、スマホ `clamp(36px, 11vw, 58px)`。行高1.2、最大2.4em |
| 抜粋 | 同ファイルの `.cover-journal__lead > small` | PC 16px、スマホ15px。行高1.6、枠は3.2em。タイトルとの間隔はPC 20px、スマホ14px |
| タグの行数と高さ | `frontend/authoring/HomeTags.tsx`、`cardHome.css` | PCの3行分は124px（36px × 3行 + 8px × 2）、ボタンが必要な場合のみ開閉枠44px。スマホは96px（44px × 2行 + 8px） |
| タグの折りたたみ判定 | `HomeTags.tsx` の `rows[3]` | 実際の折り返し位置を測定する。行数を変える場合はCSSの高さも変更する。非表示リンクは `visibility: hidden` としてフォーカス対象から外す |
| スマホの境界 | `HomeTags.tsx` と `cardHome.css` | 両方とも600px。変更時は両方を揃える |
| カードの仮表示 | `frontend/authoring/HomeCards.tsx`、`homeLoading.css` | カテゴリ枠とタイトル用の線を画像内、本文3行分の線を画像下に置く。実表示のグリッド、画像領域、本文枠を共有する。本文枠は上余白14px＋3行×28.8pxを確保する |
| シマー | `frontend/authoring/homeLoading.css` | 2.2秒、linear。下地・光の帯とも `currentColor` の10%を使用。画像面全体やタグは動かさない |
| ヘッダー | `frontend/authoring/main.tsx` の `HomeLoading` と `HeaderDock` | 仮の検索欄や丸いボタンを作らず、実表示と同じヘッダーを使う |

シマーの2.2秒は製品の調整値であり、Appleが指定した秒数ではない。動きを控えめにする判断は [Apple HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion) を参考にした。`prefers-reduced-motion: reduce` ではシマーを停止し、静的な仮表示を残す。

## ローカル検証記録（2026-09-13）

Chromeの開発環境で、API応答を保留した読み込み状態と取得後を比較した。画面幅320・390・1024・1280・1920pxで、ヒーローのタイトル・抜粋枠、タグ領域の座標と寸法、最初のカードの開始位置が一致した。ページ全体の横はみ出しとJavaScript例外もなかった。

PCのタグをEnterで展開・折りたたみできること、スマホ幅へ変更すると全タグが横スクロールで表示されること、動きを減らす設定でシマーが停止することを確認した。記事カード内のタイトルは実際の行数に応じて高さが変わるため、すべての文字線が実テキストと一致する設計ではない。

関連する `main.test.ts` の10件、型チェック、変更ファイルのBiomeチェック、Viteの本番ビルドが通過した。ブラウザ検証は一時スクリプトによるもので、リポジトリの自動テストには含まれていない。

## Editorialスタイルへの追従（2026-09-22）

実際の開発用データで記事APIを3秒、タグAPIを5秒遅らせ、幅375・1024・1440pxで比較した。先頭カードの開始位置・画像寸法と、2行目の開始位置が読み込み前後で一致した。動きを減らす設定ではシマーのアニメーションが停止する。スケルトン画像面には写真用の暗いグラデーションを適用せず、薄いグレー上にカテゴリ・タイトルの仮表示を置く。

遅延は確認用サーバーだけに設定し、アプリケーションには追加しない。タイトルが画像領域を押し広げるほど長い場合や、取得される記事数が仮表示6件より少ない場合まで、ページ全体の高さを固定するものではない。

## デプロイ後の確認

本番環境での表示、Safari・iPhone実機、スクリーンリーダーの読み上げ、実機でのフレーム落ちは未確認。次の順で確認する。

1. キャッシュ無効・低速回線でトップページを再読込し、初期表示、記事取得後、タグ取得後を比較する。通常の高速回線でも短い仮表示が目障りにならないか確認する。
2. スマホ幅390px、PC幅1024・1440・1920pxで、ヒーローとタグの下端、記事一覧の開始位置が移動しないか確認する。
3. 1行・2行・省略が必要な長いタイトル、抜粋なし、カバー画像の有無を比較する。タイトル2行分の余白と抜粋の読みやすさを判断する。
4. タグが0件・少数・4行以上になる場合、長いタグ、取得失敗を確認する。展開後の全タグ、キーボード操作、600px前後の切り替えも確認する。
5. ダークモード、動きを減らす設定、200%ズーム、Safari・iPhone実機で、シマーの明暗差、文字の欠け、スクロール操作を確認する。

位置のズレがあれば共通のレイアウト側から直す。シマーの速度だけを変更しても位置のズレは解消しない。タグの固定領域を縮める場合は、読み込み前後の安定性と、表示できるタグ数の両方を再検証する。

ローカルの再検証コマンド（対象worktreeで実行）:

```sh
mise exec -- npm run typecheck
mise exec -- npx --yes tsx --test frontend/authoring/main.test.ts
mise exec -- npm run build
```
