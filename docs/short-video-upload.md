# 短い動画のアップロード

エディタのファイル選択・ドロップ・貼り付けから動画を追加する。
ブラウザ内の専用Workerで最大1080p相当・30fpsのMP4を生成し、既存の認証付き `POST /api/uploads` が発行した署名付きPOSTでS3へ送信する。
配信URLは既存のCloudFrontを通る `/assets/uploads/YYYY/MM/UUID.mp4`。
MediaConvertや新しいAWSリソースは使わない。

## 変換

- 入力は500MB以下、60秒以下のSDR。HDRやデコード非対応の入力は理由を表示して停止する。
- H.264（映像4.5Mbps）を生成し、AV1生成対応の端末ではAV1（2.3Mbps）も生成する。
- 元動画をアップロードしない。映像は縦横比を保って縮小し、拡大しない。
- AAC音声はコピーし、他の対応音声はAACに変換する。音声の脱落を許さない。
- 出力は各50MiB以下。サーバーの署名付きPOSTも同じ上限と `video/mp4` を強制する。
- キャンセルはWorkerと送信を中断する。すでに送信を完了したファイルは残る（既存画像と同様、自動削除はしない）。
- 画像と動画の混在ドロップは、分けて操作するよう案内する。

## 保存と再生

本文には `:::video H264のパス AV1のパス 1920x1080 :::` を1行で保存する。AV1のパスと寸法は省略できる。
新しいアップロードには変換後の寸法を保存し、再生前からその縦横比で表示する。寸法がない既存の動画は16:9で表示する。
ファイルのドロップ時には本文を変更せず、変換とすべての出力ファイルのアップロードが成功してから動画を挿入する。
挿入した動画は本文の自動保存でこの記法になり、失敗・キャンセルした動画の記法は追加しない。
エディタと公開HTMLは同じ形式を解釈し、AV1、H.264の順にsourceを並べたvideoを表示する。
対応する保存先のパスだけを受け入れ、外部URLや任意HTMLをこの記法から生成しない。
自動再生はせず、`controls`・`playsinline`・`preload="metadata"` を指定する。
配信URLに `#t=0.001` を付けて初期フレームを表示する。再生前にもメタデータと初期フレーム用の通信が発生し、取得量はブラウザに依存する。
編集時は動画の下に「記法を編集」「本文から削除」を表示する。記法の編集ではパスと寸法を変更できる。
削除は本文からの除去のみで、アップロードしたファイルは残る。エディタのUndoで本文への削除を取り消せる。

## 検証

2026-09-08、Mac Chrome 152で元の `IMG_0010.MOV`（371,338,660 bytes、HEVC、約33秒）をエディタへドロップした。
実際のWorkerがH.264 19,612,737 bytesとAV1 10,250,482 bytesを生成した。
外部APIとS3の送信先をPlaywrightで置き換え、両MP4の送信、動画ノード挿入、自動保存本文を確認した。
送信されたAV1を同じブラウザで再生し、1920×1080で再生位置が進むことを確認した。
キャンセル後にファイル入力が再び有効になることも確認した。

独立した試作では、ユーザーのiPad SafariでH.264入力からAV1生成が完了した（106.37MB→9.95MB、37.6秒）。
