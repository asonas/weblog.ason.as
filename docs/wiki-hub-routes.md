# 未作成ハブとスラッシュを含むページ名

Wikiリンクは本文ページが未作成でも公開HTMLに残す。
記事公開時に、参照された未作成の名前へ既存のアプリシェルを配信し、ハブのリンク元と本文作成の操作へ接続する。
ハブ用の空レコードはDBに作らない。本文のある記事を上書きしないよう、ハブのS3書き込みは条件付き作成とする。
後から本文を保存すると通常の記事公開処理が同じキーに記事HTMLを保存する。

`KORG multi/poly` のスラッシュは表示名の一部。URLでは `%2F` に変換する。
ローカルのMarkdownファイル名でもスラッシュをエンコードし、ディレクトリにはしない。
APIは経路の途中でデコードされたスラッシュも同じページ名として受け取る。
空のパス要素、`.`、`..`、配信用の予約済みプレフィックスは受け付けない。

## 検証

- 公開Markdownの未作成リンク、名前の検証とエンコード。
- API経由でスラッシュ名のハブを開き、同名ページを保存して再取得。
- 公開処理によるハブ配信と条件付き作成、キャッシュ更新パス。
- 専用Chromeの390px画面で、公開記事から `sub` と `KORG multi/poly` を開き、リンク元タブから参照記事の詳細を表示。JSエラーなし。
- ブラウザ記録: `/tmp/wiki-hub-browser.json`、`/tmp/wiki-hub-slash.png`。

## 本番適用

1. API Gatewayの `/api/routes/{route+}` をTerraformで反映する。保存したplanを確認してapplyし、再planで残差を確認する。
2. コードをデプロイする。
3. まず対象記事1件を再生成し、ハブの作成・URL・表示名・リンク元・キャッシュ更新を本番で確認する。
4. 残りの既存公開記事を再生成する。再生成時の外部通知は送らない。
